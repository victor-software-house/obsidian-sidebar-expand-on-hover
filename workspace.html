Problem

The NLP parser in tasknotes-nlp-core@0.1.0 uses bare regex (\b(high|important)\b) to match priority and status from titles. This silently mangles natural language:
- "High performance system" -> "performance system" with high priority
- "Open source contribution" -> "source contribution" with open status

Key Discovery

The prefix/trigger system already exists in tasknotes-nlp-core. The TriggerConfigService and DEFAULT_NLP_TRIGGERS define:

JavaScript
// defaults.js
export const DEFAULT_NLP_TRIGGERS = {
triggers: [
{ propertyId: "tags", trigger: "#", enabled: true },
{ propertyId: "contexts", trigger: "@", enabled: true },
{ propertyId: "projects", trigger: "+", enabled: true },
{ propertyId: "status", trigger: "*", enabled: true },
{ propertyId: "priority", trigger: "!", enabled: false }, // <-- DISABLED
],
};

The problem: ! priority trigger is disabled, so extractPriority() falls through to bare-word regex matching.
